# 让人留下来：反馈与激励（提案，待 Josh 决定）

2026-09-18。起因：Josh 提出「让用户爱上、留在这里，像游戏一样有反馈、能激励人」。

这条诉求和 `09-dangerous-directions.md`（"不要变成游戏化产品"）、`02-user-psychology.md`（"KPI 疲劳"）、
`05-emotional-design.md`（错误情绪："我要坚持""我今天必须完成"）表面冲突。本文的立场是：
**冲突的是游戏化的外壳，不是游戏的内核。外壳不要，内核要。**

## 一、先拆开：游戏里真正让人回来的是什么

不是分数。分数是计分板，不是动机。真正起作用的四件事：

1. **世界因我而变** —— 我上次来做的事留下了痕迹，这次进来看得见。
2. **每次有一个小发现** —— 不是奖励，是"原来是这样"。
3. **有未完的钩子** —— 走的时候故事没讲完，我知道下一段在哪。
4. **进展是可见的空间，不是数字** —— 地图被点亮，而不是进度条到 63%。

这四条全部可以落在 Journey 上，且不违反任何一条原则。

## 二、红线：这些不做（做了就变成另一个 App）

| 不做 | 为什么 |
|---|---|
| 连续天数 / streak / 断签提示 | 宗教场景下断签 = 罪疚感。`01-vision.md` 的用户恐惧第一条就是"中断后的失败感" |
| 积分、等级、经验条 | 把读经变成刷量，撞 Reading First |
| 徽章墙、成就系统 | 收集欲会取代阅读欲，且是典型"工具感" |
| 排行榜、好友对比 | 撞"羞耻：比较心理" |
| 每日推送催促 | 撞 Gentle Return——"回来不是因为任务" |
| 完成率 / 百分比 | 撞"进度焦虑" |

**判断标准**：这个反馈是在说「你做得够不够」，还是在说「你走到哪了」？前者一律不要。

## 三、要做的五条（按投入从小到大）

### 1. 留下痕迹：读过的经文会"变色"
读过的章节在目录里有极轻的质感变化（纸色微深、边缘有一道细痕），**不显示数字、不显示比例**。
用户滑目录时自然看到"我走过这一片"。这是最便宜也最接近游戏内核的一条——它只陈述事实，不评价。

### 2. 结束时的钩子：每次 Journey 收尾留一句"下一段在哪"
现在一段结束就结束了。改成结尾一行不是总结、是预告的句子（"三天后，他在旷野遇见了……"）。
游戏里所有让人"再来一把"的设计都是这个结构。成本极低，只是文案。

### 3. 回归时的认出：隔了几天回来，App 认得你
不是"你已经 5 天没来了"，而是"我们上次停在 X，要接着走吗"。
同一个信息，一个在问责，一个在陪伴。这条直接实现 `Gentle Return`。

### 4. 一次一个发现：每段 Journey 保证一个"意外"
`06-journey-system.md` 已经写了"一个发现"，但目前是文档里成立、界面上不成立。
要把它显性化成一个独立的、短的、有呼吸的画面（一个地名、一个当时的物价、一句原文的字面意思），
让用户有"这个我不知道"的瞬间。这是探索作为**奖励**而非入口的正确形态（原则 4）。

### 5. 空间化进展：地图 / 时间线（`10-parking-lot.md` 已停车）
把"走过多少"表达成地图上被点亮的地点，而不是任何数字。这是最贵的一条，
但它是唯一能长期承载"我在这个世界里越走越深"的载体。建议等前四条验证后再动。

## 四、优先级建议

先做 2 和 3（纯文案 + 一句回归语，一天内能完成，风险接近零），观察次周留存。
再做 1。4 需要内容生产配套。5 暂不动。

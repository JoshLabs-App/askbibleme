## 三、这张表已经收口了，不要再问 Josh（2026-09-25）

**Josh 2026-09-25：「不需要放授权信，你处理就好了」。** 在此之前他已经说过三次
（2026-09-23「NIV 这个是有授权的」「那个是有授权的」「授权了」、2026-09-24「5 有的」）。

所以**这件事到此为止**，以后谁（包括下一个线程的我）再看到最后 4 行都按下面这样理解，
不要再开一轮「这个有没有授权」的讨论，也不要再向 Josh 索取授权文件：

- **授权是有的**，依据是 App 所有者本人的反复确认。这就是本表的凭据。
- **授权方和授权文件刻意不登记**，是 Josh 的决定，不是遗漏，**不要再标「待补」**。
- **我核实不了，也不需要核实**——版权责任在 App 所有者，不在实现代码的人。

唯一仍然要做的是第四节：**变现之前必须回头重新确认一遍**。那时候档位会变，
口头确认不够用，需要落到纸面；在那之前不必碰。

（`YVP_APP_KEY` 覆盖的那几个本来就不着急：官方 API 拿得到本身就是授权的证据，
实际清单见 `providers/youversion.ts` 的 `YOUVERSION_LICENSED_VERSION_IDS`。）

## 四、不收费（Josh 2026-09-25）

**Josh 2026-09-25：「这个软件是不收费的」。** 所以上面所有版权译本走的都是**非商用档**，
这是成立的，不是将就——这一节是前提，**不是待办，不用再提醒**。

事实核对（2026-09-25）：`01查经` 全仓搜不到任何广告 / 内购 / 订阅的代码
（AdMob、AppLovin、StoreKit / SKProduct、Play Billing、RevenueCat 全无命中）。
没有广告这点尤其要紧——**多数非商用授权把「带广告」也算成商用**，免费但挂广告一样会踩线。

以后要改这件事（开始收费、加订阅、或者只是挂广告）**再回来看这一节**，
那时候整表都要重新确认档位，口头确认不够用，需要落到纸面。在那之前不必碰。

**第三节的收口同样适用**：不要因为「代码里看不出授权」重新判定这几个译本。

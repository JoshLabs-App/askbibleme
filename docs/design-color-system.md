## 一、现状：我们其实有两套互不相干的配色

### 1. 主色系（做得是对的，不要动）

「羊皮卷 / 沉香木」体系，三端一致：

| 角色 | 浅色 | 深色 |
|---|---|---|
| 画布 canvas | `#ECD9B9`（App）/ `#FDF8EC`（原生首页） | `#1A1512` |
| 卡面 surface | `#F5EBE0` / `rgba(255,252,245,.88)` | `#292524` |
| 正文 ink | `#1C1410` | `#F4EBE1` |
| 次级 muted | `#5C4030` | `#D8C8B4` |
| 沉香木 深棕块 | `#3D2E24` ~ `#4A382C` | 同 |
| 羊皮强调 accent | `#D97707` | `#D97707` |
| LOGO 黄 | `#FFB103` | `#FFB103` |

这一套是暖色、低饱和、偏橙棕的**单一色相家族**（hue 25–45），加上一个高饱和的品牌黄作唯一亮点。
成就徽章的青铜/白银也落在这个家族里。**整体气质是对的。**

### 2. 加亮 / 状态色（问题全在这里）

| 出处 | 色值 | 问题 |
|---|---|---|
| 划重点色板 · 绿 | `#7BC96F` | GitHub 贡献图绿，冷调、荧光感 |
| 划重点色板 · 青 | `#0FBCDB` | 纯青，饱和度 100%，在羊皮纸上像贴纸 |
| 划重点色板 · 粉 | `#F48FB1` | Material Pink 200，糖果粉 |
| 引号内人物说话 | `#38486C` | 冷海军蓝；**深色模式下同值，几乎看不见（真 bug）** |
| 年日格子 / 人生电池 / 金句坞开关 | `#34C759` | iOS 系统绿，和仓库里已有的 `READ_DONE_ACCENT` 又不是同一个绿 |
| 首页环 / 成就「已获得」 | 橄榄绿（另一个绿） | 全 App 出现了**三种互不相干的绿** |

**结论**：不是"主色不好看"，是**加亮层从别处抄了四五个互不相干的 stock 颜色**，
每一个单看都没问题，放在沉香木 + 羊皮纸上全都像外来户。这正是用户说的"整体不匹配"。

## 二、设计原则（后面所有取色都从这三条推出来）

1. **羊皮纸上的高亮是"颜料"，不是"色块"。**
   真实的荧光笔是半透明颜料叠在纸上，纸的暖底会透上来。所以高亮一律定义成
   `颜料 hex + alpha`，叠在 canvas 上，而不是直接给一个不透明色。
   这样无论浅色深色，高亮都自动"长在纸里"。

2. **四支笔要等亮度，不能有一支跳出来。**
   目标是叠加后的合成色亮度 L\* 接近（浅色 ≈ 78–84，深色 ≈ 22–28）。
   等亮度 = 不同颜色只表示"分类不同"，不表示"这条更重要"。

3. **冷色要先"晒旧"再进来。**
   这套视觉是十七世纪抄本的语气。任何冷色（蓝、绿）进来之前，先把饱和度压到 35% 以下、
   往黄侧偏一点色相，变成"褪色的墨水蓝""橄榄绿"，就不再违和。
   纯青 `#0FBCDB`、糖果粉 `#F48FB1` 这类电子原色，在这个语境里没有位置。

## 三、方案 A：划重点四色板（核心改动）

命名按颜料本身，不按"红黄蓝绿"，方便以后在设置页直接给用户看中文名。

| 名称 | 颜料 hex | 浅色 alpha | 叠在 `#ECD9B9` 上的效果 | 深色 alpha | 替代原来的 |
|---|---|---|---|---|---|
| **灯油黄** | `#FFB103` | `0.45` | ≈ `#F4C767` | `0.28` | `#FFB103`（保留，品牌色） |
| **橄榄绿** | `#A3B565` | `0.50` | ≈ `#D8D486` | `0.28` | ~~`#7BC96F`~~ |
| **青石蓝** | `#4E86A0` | `0.46` | ≈ `#A6B7B4` | `0.32` | ~~`#0FBCDB`~~ |
| **石榴红** | `#C0625F` | `0.42` | ≈ `#DAA995` | `0.30` | ~~`#F48FB1`~~ |

- 四支笔都在 **低饱和 + 中高亮度**区间，和羊皮纸是同一个"年代"。
- 黄保留品牌色不动：它同时还是双击收藏标记、朗读跟读高亮的底色，动了会连锁。
- 深色模式下用同一组颜料、只降 alpha，**不需要另建一套 hex**，三端各自只存一份色板。

> 落地点（三端同步，值必须一致，否则会员同步的 `highlights` blob 会串色）：
> - `lib/read/read-verse-text-highlights.ts`
> - `apps/askbible-ios/AskBible/Model/VerseTextHighlights.swift`
> - `apps/askbible-android/app/src/main/java/me/askbible/native_/data/VerseHighlightStore.kt`
>
> **注意：已有用户数据里存的是旧 hex 字符串。** 改色板必须带一张
> 旧→新映射（`#7BC96F→#A3B565` 等），在 `normalizeColor` 里做一次迁移，
> 否则老用户画过的重点会被 `normalizeColor` 全部打回默认黄。

## 四、方案 B：一个 App 只准有一种绿、一种蓝

### 1. 一个 App 只准有一种绿 → `#65775C`（橄榄）/ 深色 `#A8BC72`

**不用新造色**：仓库里早就有 `READ_DONE_ACCENT = "#65775C"`（读经目录"已读完"、
今日读经统计在用），本来就是橄榄绿、本来就在羊皮家族里。全部收敛到它。
iOS 系统绿 `#34C759` 全部下掉（人生电池"还剩"、年日格子、金句坞开关）。

> 2026-09-19 已落地。深色版 `READ_DONE_ACCENT_DARK = "#A8BC72"` 一并加进
> `lib/read/read-parchment-accents.ts`。

### 2. 引号内人物说话 `#38486C` → `#54617A`（浅）/ `#A8B4CC`（深）

- 现值在深色模式是**实打实的可读性 bug**：深蓝字压在 `#1A1512` 上。
- 新值仍然是"蓝"，能和神的话语 `#994812` 区分，但饱和度压下来了，不再冷得跳。

## 五、方案 C：加亮层的"亮度预算"

这是"整体不匹配"的第二层原因——**不只是色相问题，还有面积和明度问题**。

规则：一屏之内，高饱和色（品牌黄、砖红、任何 alpha>0.4 的高亮）**总面积不超过 10%**。
具体到各处：

- 首页"接着听"深棕卡是全屏最重的块 → 它上面的按钮就**只能用白底棕字**，不能再上黄色。（现状是对的，保持）
- 迷你播放器已经是深棕条 → 里面的进度条用米白 `#F4EBE1`，不要上品牌黄。（现状是对的）
- 圣经页正文区 → 只有高亮笔和节号可以带色，其余一律 ink/muted。
- 徽章墙 → 青铜/白银本身信息量已经很大，**标题文字不要再上绿色**，改用 muted 棕 + 橄榄绿小圆点。
